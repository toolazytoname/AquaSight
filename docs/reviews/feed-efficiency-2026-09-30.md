## 已实现

- **订阅流**：SQL 使用主来源表达式索引及 hidden 排除，投影筛选、排序所需字段；保留 URL 安全检查、关键词、次来源过滤、未读过滤、GitHub 观测时间及并列 ID 排序。按筛选后的页面 ID 读取完整事件，保持精确 total 与原有 offset cursor。
- **最新流 / 开源入口**：复用公共轻量字段索引，完成原有内容与偏好过滤，再读取当前页正文。最新流取消 480 条截断，深分页继续有效。
- **精选 / 审阅**：直接读取快照中的精选 ID，不先加载整个事件表。精选仍先应用关键词、分类、来源及未读过滤，再执行精选规则。
- **早报**：直接读取当日早报快照，不额外读取事件表。
- **所有 API 的 snapshotAt**：只查询 snapshots.at，不读取完整快照 JSON。精选 ID 也单独投影，不搬运快照 items。
- **共享内容缓存**：D1 binding 对象隔离，默认 60 秒 TTL、500 条、约 4 MB 字符串内存估算上限、LRU、并发 miss 去重、每个调用者取得独立副本。缓存公共字段索引、事件页面、详情、成员、内容快照和计数；不缓存账户响应、偏好、收藏、已读及凭据。调度租约和发送标记快照绕过内容缓存。
- **失效与边界**：采集、事件/文章写入、成员写入、内容快照、清理、导入后失效；批次部分失败亦失效。失效前的在途读取不能填回旧缓存。无效游标安全回到首屏；暖缓存期间行被删除或来源变化，读取正文时复核订阅条件，并按请求过的 ID 推进游标。
- **索引迁移**：worker/migrations/20260930_read_indexes.sql 使用 CREATE INDEX IF NOT EXISTS，基于已有 JSON 的来源表达式建立索引，无新增必填字段、无 ALTER/backfill。production/staging npm 发布脚本及 CI 先运行迁移。

## 实际边界

这不是全部过滤与排序都在 SQL 内执行的 LIMIT/OFFSET：为保留 JS 的 URL 判定、日期回退、内容分类、Unicode 搜索及个人未读语义，冷缓存时仍读取匹配来源的轻量字段，最新流冷缓存则读取非 hidden 的字段索引；排序与精确计数在这些字段上完成，正文按页 ID 读取。缓存命中减少重复数据库读取，不能据此承诺具体用户容量。无精选 ID 的旧快照仍保留原有全量精选回退路径。

缓存是 Worker 实例内的，不保证跨实例立即失效：其他实例写入后，旧内容最长可保留约 60 秒；同步/认证/账户偏好及调度运行状态不受内容缓存控制。返回值和 total 在并发内容更新期间不构成数据库快照隔离，可能出现页面少于 limit；游标会继续前进。
