# GitHub 项目发现

用户要求增加 GitHub 信息源，方便发现值得关注的项目。由 Codex 拆解和审查、OpenCode `litellm/glm-5.3` 实现；Codex 完成边界修复与独立验收。基于 `36cc2c2`，本轮尚未提交、推送或部署。

## 用户可见变化

桌面导航和手机底栏增加「开源」，路由为 `#/opensource`。项目卡片显示语言、星数、日榜/周榜增长；详情保留仓库名、用途、入选信号、最近维护日期和许可证。未提供许可证时显示「未知」。用途优先显示已有中文 AI 整理结果，仓库名和编程语言保留原文。未整理时保留原始描述，不假装已经翻译。

项目入口支持现有搜索、分类、来源、未读筛选和收藏。API 与静态快照备用页面均可使用；隐藏项目和屏蔽来源依然生效。项目榜单合并不会被称为“多家媒体报道”。

## 信息源与筛选

| 来源 | 请求/轮 | 内容 |
|---|---:|---|
| 原 `github` | 1 | 最近 7 天创建、至少 20 星的新仓库；排除 fork、归档、禁用、缺描述和既有垃圾规则命中的项目 |
| 原 `github-trending` | 1 | GitHub 每日 Trending；增长注明“今日” |
| 新 `github-trending-weekly` | 1 | GitHub 每周 Trending；增长注明“本周” |
| 新 `github-maintained` | 最多 3 | AI ≥1000 星且近 60 天维护；开发工具 ≥3000 星且近 90 天维护；Web ≥5000 星且近 90 天维护 |

维护项目搜索按主题分桶，每桶最多读取 12 个结果。本地重新核对星数和维护窗口，过滤 fork、归档、禁用、短描述、既有垃圾规则及明确自动生成的索引/镜像内容。自动索引规则限定于特定名称和描述，不因名称包含任意 `index` 子串就排除正常产品。

合格候选在各桶内按星数排序，再轮询各主题：三个主题各最多 4 条、同一作者最多 2 条、同一语言最多 5 条，总计最多 12 条。不足时可以少出，不拿不合格项目填满。入选信号是筛选依据，不是安全审计或实际使用评价；这些阈值偏向已有一定积累的项目，小型项目由新建仓库和 Trending 来源补充。

每轮 GitHub 总计最多 6 个 HTTP 请求，其中搜索 API 4 个。按现有每日 4 轮，正常最多 24 次请求，比原先增加 16 次；手动重跑/兜底会另计。维护来源的 3 次搜索顺序执行，无逐仓库 README、许可证、release 等额外 API 请求。既有 GITHUB_TOKEN 可用则使用，无 token 可读公开来源；不新增凭据。403/429 报来源失败，`incomplete_results` 保留告警，经采集、状态 API 到设置中的状态详情可见。

## 去重与时间

- 同一仓库的全名按小写作为强合并键，日榜、周榜和搜索结果合并为一张卡片，各自增长窗口与入选信号保留。
- Hacker News 先收录同一仓库时，也从其他成员提取仓库元数据，不能因为主来源是 HN 就从项目入口消失。
- `githubRepo.observedAt` 是本轮观察时间，独立于稳定的 `firstSeenAt` 和事件 ID；聚类取匹配仓库成员的最新观察值。
- 开源入口按最近观察时间排序，超过 7 天未被观察到的条目退出入口。旧数据无该字段时兼容首次发现时间；已收藏快照不因此删除。
- `pushed_at` 只代表仓库活动，不冒充新闻发布或版本发布时间。新建来源仅使用真实 `created_at` 作创建时间；缺失时不拿 push 时间替代。

## AI 与兼容性

继续使用已配置的 LittleLM `free`，模型配置和价格设置不变。在原单轮 40 条整理上限内，给项目最多 4 个优先位置（`MODEL_ENRICH_REPO_SEATS` 可设 0–100），保留早报候选优先权；有空位则补入，满额时替换末尾非早报、非项目项，不突破总上限。

AI 只依据稳定的项目名称、语言和描述解释用途/适用场景，不把星数、增长或观察时间写入生成正文。动态信号直接由结构化字段显示，避免星数变化导致反复生成。项目描述变化会使缓存失效；动态统计变化不会。已有仓库信息足以整理时不再抓取仓库网页正文。

可选 `githubRepo`/`observedAt` 字段沿文章、聚类、公开快照、API 和收藏保留；不修改数据库 schema。Service Worker 缓存版本 v18 → v19。
